# DryRun — see every algorithm run

A static site (HTML + CSS + vanilla JS, no build step, no backend). Paste a LeetCode URL → get a beginner solution,
an optimized solution, an animated trace, a diff "morph" between them, a complexity race, a memory trick and Anki cards.

* **117 unique problems, 8 role tracks × 25 = 200 drills** (problems are shared between tracks), all preloaded in `js/data/`.
* Every Python problem has **both variants executed against embedded tests** (206 runs). The 14 JavaScript problems have
  async tests too (28 runs). See *Verification*.
* Problems outside the library are generated by an LLM *in the visitor's browser* using their own key (or a free tier).

## Run / deploy
```
python3 -m http.server 8000      # then open http://localhost:8000
```
Deploy the folder as-is to GitHub Pages, Cloudflare Pages, Netlify or any static host. `dist/dryrun.html` is the same
site as one self-contained file (only the Google Fonts link is external; it falls back gracefully offline).

## Tracks
`js/data/tracks.js` — Data Science, AI Engineer, Forward Deployed Engineer, AI/ML Researcher, Software Engineer,
Backend, Frontend, Core Developer. Edit the `ids` arrays (25 slugs each) to re-curate.

## Add a problem
Add a record to any `js/data/pN.js` with `DR.add({...})`:
```
id (LeetCode slug), n (number), t (title), d ('E'|'M'|'H'), tg (tags), pat (pattern name), br (one-line brief),
bt/bs (variant 1 time/space), ot/os (variant 2 time/space), b (variant 1 code), o (variant 2 code),
trick, real, viz, lang ('py' default | 'js'), test + exp (python) or jt + je [+ jeb] (js)
```
* In code, a trailing `#? note` (JS: `//? note`) marks a slow line in variant 1 (red); `#! note` marks a key line in variant 2 (green).
  The diff morph and the complexity race are derived automatically from the two code strings.
* `viz` is either `{sim:'hash'|'twoPtr'|'window'|'bsearch'|'dp1'|'dp2'|'graph'|'bt'|…, …params}` (see `js/sims.js`)
  or `{flow:[DR.f(note, arrayCells, {h,g,x,p,w,aux,grid,…}), …]}` for a hand-written trace.
* Data files use `String.raw`, so code must not contain backticks or `${`.
* Add the slug to a track in `tracks.js`, then run the checks below.

## AI for new problems
Settings (key icon, top right) accepts any OpenAI-compatible `/chat/completions` endpoint, plus Anthropic directly.
Presets: Groq, Google Gemini, OpenRouter, Cerebras, Mistral, GitHub Models, NVIDIA NIM, Hugging Face, DeepSeek, Qwen,
OpenAI, Anthropic, Pollinations (experimental, may need credits) and Custom. Free tiers and model names change often —
use *List models* or edit the Model field. Keys live in `localStorage` and go only to the provider you choose.
Generated problems are cached in the browser (`dr-mine`) and can be exported as JSON or Anki cards.
**AI output is unverified — read the code before trusting it.**

## Anki
* *Download cards* → tab-separated `.txt` (2 cards per problem: pattern recall, write-the-code) → Anki *File → Import*.
* *Send to Anki* → AnkiConnect (add-on code `2055492159`). In the add-on config add this site's origin to
  `webCorsOriginList`, keep Anki open. Without that, browsers block the call and the site shows a hint.

## Verification (what was actually run)
```
node tools/dump.js > /tmp/dr.json && python3 -I tools/check.py /tmp/dr.json   # both variants of every python problem + track integrity
node tools/checkjs.js                                                         # both variants of every JS problem (async, real timers)
node tools/frames.js                                                          # every animation generates valid frames
npm i jsdom && node tools/smoke.js                                            # every route, every animation, tabs, morph, race, AI retry path (mocked), Anki
python3 tools/bundle.py                                                       # dist/dryrun.html
```
Not covered: pixel-perfect rendering in every browser, and the real third-party endpoints (they need network and keys).
